## CyTools_MeshStudio {#cytools-meshstudio}

MeshStudio combines reconstruction, view generation, remeshing, UVs, PBR texturing, rigging, motion, editing and inspection. Workflows chain these operations for a single input or a folder.

## Start {#demarrer}

Double-click on CyTools_MeshStudio.exe. The Dear ImGui interface opens directly, without a terminal and without JSON to edit. It starts in English; choose Options → Language → French to switch it to French — the entire interface is translated, including parameter tooltips.

Since the GitHub release: decompress `CyTools_MeshStudio-<version>-windows-x64.zip` into a short path (QuadWild fails beyond about 240 characters of path, and the tool tells you instead of running), then double-click the executable. Nothing needs to be installed: the archive contains the application, a bundled Python 3.12 with its packages, `uv`, and the two native geometry engine programs. The engines and weights are built and downloaded from the Installation tab (several dozen gigabytes in total).

On Linux, `CyTools_MeshStudio.sh` launches the same interface, but nothing has been executed on Linux here: see the limitations at the end of the file.

## Pages {#les-pages}

Since version 0.1.2, pages open from the sidebar, in two groups: 'Workspace' (Tools, Workflows, 3D View) and 'System' (Installation, Updates, Log, Advanced Operations, Options). The status bar at the bottom shows the current task or the last error. Tool, workflow, and model lists have a search field.

- Tools: the 40 operations, organized by usage (Reconstruction, Views, Topology, UV, Texturing, Editing, Inspection, Rigging, Movement, Workflow, Maintenance). Each operation has its true controls, advanced settings folded away, the choice of engine when there are multiple, real progress, cancellation, and its results.
- Workflows: chain these operations, choose what each step receives from the previous one, record the chain and replay it on a file or an entire folder.
- Installation: the state of each engine and each model — installed or not, size, license, restricted access — with buttons to install or repair an engine, install the weights of a missing model, and import a file whose license you accept personally (the application never asks for these sites' credentials: it imports the file you have downloaded).
- Updates: the three feeds (application, engines, weights). For the application: check a published version on GitHub (repository `MrMybal/CyTools_MeshStudio`, declared in the manifest and modifiable in the tab), prepare it, activate it at the next start, and revert. Nothing is replaced while the application runs, and `data/` is never touched.
- 3D View: the result opens automatically there; orbital or free camera, scenes and lighting.
- Application Log, Advanced Operations and Options (language, theme among the five of CyUI, compact or comfortable density, text size, licenses, saving and reloading the configuration).

## LocalMesh+ : an image towards a production model {#localmesh-une-image-vers-un-modele-de-production}

Two workflows go further than LocalMesh alone:

- Image to production mesh (LocalMesh+): background removal → LocalMesh in quality `high` (the detailed model, kept for comparison) → reduction to 60,000 faces → quads aligned on the forms by QuadWild → 4K texture generated by TRELLIS.2 for this precise quad mesh, with a baked normal map from the detailed model. OBJ keeps the quads; GLB is triangulated, as glTF requires.
- Option « refine » (unchecked by default, in the steps list): TRELLIS.2 regenerates the detail of the LocalMesh model on the 1536 grid while keeping its form before the reduction and quads; the normal map is then baked from this refined model. It also exists alone: Refine a mesh with TRELLIS.2 (LocalMesh), on any aligned mesh. Unchecked, the step lets the LocalMesh model pass as is.
- Image to production mesh with generated views (experimental): the same chain, but Wonder3D generates first the right, the left, and the back. Only for a well-right-facing view: on an airplane viewed from three-quarters above, the generated views were tilted and the merged form deformed (the quads and the texture followed to within 0.1% accuracy).

- Image to production mesh with Hi3DGen: the same chain, with Hi3DGen (Stable-X) for the form: the image becomes a clear normal map (StableNormal YOSO), then a mesh (TRELLIS v1 re-trained on normal maps, 256 grid). Check « refine » to regenerate the detail on the 1536 grid before the quads and texture. Hi3DGen also exists alone: Image to mesh (Hi3DGen), Tools tab, Reconstruction category.


## The other provided workflows {#les-autres-workflows-fournis}

| Workflow | Input | Purpose |
|---|---|---|
| Image to quick preview (LocalMesh draft) | an image | a first glimpse in about a minute, before a long calculation |
| Image to maximum-quality mesh (LocalMesh max) | an image | grid 1536, 400 000 faces, atlas 8K ; close other programs that occupy the GPU |
| Image to game asset (LocalMesh, AutoRemesher) | an image | about 4,000 quads, 2K texture and normal map, ready for Unity, Unreal or Godot |
| Image to rigged character (LocalMesh, UniRig) | an image | the same asset with about 6,000 quads, then skeleton and skinning UniRig |
| Image to 3D print (STL) | an image | larger piece, holes closed, Z up, 100 mm high, STL |
| *Compare the shape engines on one image* | an image | the same background-removed input given to TripoSR, SPAR3D, Hi3DGen and LocalMesh; a failed engine does not stop the others |
| Four photos to production mesh (LocalMesh+) | a folder of four photos | the production pipeline, starting from real photos of all four sides |
| Photos to textured mesh | a folder of four photos | LocalMesh `high` in four views |
| Mesh to game asset | a textured mesh | about 4,000 quads, with its own texture applied to it |
| Retopologize a textured mesh (QuadWild, texture kept) | a textured mesh | quads QuadWild, sa propre texture appliquée dessus, map normale depuis l'original |

Four photos of the same subject: put them alone in a folder, named according to their side (`statue-front.jpg`, `statue-droite.jpg`, `statue-gauche.jpg`, `statue-dos.jpg`; `face`, `right`, `left`, `back` also work), then choose this folder in Entry › Folder. These workflows take the files from the folder together (setting Files from folder, saved with the workflow); the others do an execution per file.

To start: go to the Workflows tab → select the workflow → Input › File: your image → Run the workflow. Expect several minutes of full CPU usage (LocalMesh `high`, then QuadWild on CPU, followed by the texture). The results are in the job folder, one step per subfolder numbered by its position in the workflow: `2-shape` (the LocalMesh result alone), `3-refine` (if the option is checked) and `6-texture` (`textured.glb`, `textured.obj`, the maps and `texture-report.json`).
