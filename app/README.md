# CyTools_MeshStudio — developer notes

The user-facing guide is `../LISEZ-MOI.md`; the design is in `Docs/Architecture.md` and
`Docs/Workflow.md`; what was actually executed is in `../data/reports/VALIDATION.md`.

What the repository carries and how to rebuild `runtime/` from a clone is in `../README.md`;
`data/reports/` is not versioned. The licences of everything fetched at installation are in
`Docs/ThirdPartyNotices.md` (`scripts/build_notices.py`).

Built on the [CyToolsCore](https://github.com/MrMybal/CyToolsCore) SDK 0.9.0 (GPL-3.0),
installed by `requirements.txt` from its repository. The application process only validates, schedules and
reports: every model and every native program runs in a worker started with the interpreter of
its engine (`engines.json`). There is one `Runtime` behind the interface, the CLI and MCP.

## Layout

```
CyTool.json           generated — never edit by hand, see build_manifest.py
build_manifest.py     rebuilds the manifest from the absorbed Tools' schemas + the new ops
legacy-manifests/     the manifests of the eleven absorbed Tools, read by build_manifest.py
engines.json          the seven engine environments, their sources and their pins
setup_engine.py       builds one engine environment at its final path
tool.py               create_runtime: registers every handler, then run_cli
desktop.py            graphical entry point started by the launcher
updates.py            the three update streams; also runs as `--apply` at the next start
meshstudio/           paths, engines, backends registry, operations, workflow runner
workers/              one worker per backend, run by that engine's interpreter
gui/                  Dear ImGui panels: tools, workflows, installation, updates
models/catalog.json   generated by scripts/build_catalog.py
models/install.json   what an absent model needs to become installable
scripts/              migrate_assets.py, build_catalog.py, install_model.py, update_locales.py,
                      build_notices.py, build_release.py
tests/                forms, interactions, MCP, cancellation, updates
```

## Release archives

`runtime\python\Scripts\python.exe app\scripts\build_release.py` builds, from a committed tree
(`--ref`, default `HEAD`), the two archives a GitHub release carries: `-app.zip`, exactly
`git archive` of the commit, which the Updates tab stages; and `-windows-x64.zip`, the same
under a top folder plus the launcher compiled with MSVC, an embeddable CPython with the
application's packages, `uv` and the native programs, each pinned by URL and SHA-256 in the
script and recorded in `runtime/RELEASE.json` inside the archive. Nothing from this machine's
`runtime/` goes into them, and neither the engines nor the weights: what `.gitignore` keeps out
of Git stays out of the release by construction.

## After changing anything

```powershell
runtime\python\Scripts\python.exe app\build_manifest.py
runtime\python\Scripts\cytools.exe validate app\CyTool.json
runtime\python\Scripts\python.exe app\scripts\update_locales.py
runtime\python\Scripts\python.exe app\test_tool.py
runtime\python\Scripts\python.exe app\tests\test_updates.py
runtime\python\Scripts\python.exe app\tests\validate_forms.py
runtime\python\Scripts\python.exe app\desktop.py --ui-test-interactions
runtime\python\Scripts\python.exe app\desktop.py --ui-test-interactions --ui-test-language=fr
```

Never run two of them at the same time: the SDK gives the data directory to one runtime at a
time, and the second start refuses (with a message box, not silently).

`update_locales.py --check` must report **0 strings without a French translation**. New strings
go into `scripts/update_locales.py` (interface, fields, operation names and descriptions) or
`scripts/locales_fr_parameters.py` (parameter tooltips).

## Command line and MCP

```powershell
runtime\python\Scripts\python.exe app\tool.py create-client --name "Dev" --permission filesystemExternal --permission network
```

```powershell
runtime\python\Scripts\python.exe app\tool.py invoke diagnose --params "{}"
```

```powershell
runtime\python\Scripts\python.exe app\tool.py --data-dir data\jobs mcp
```

An MCP client launches that last command with absolute paths. `--timeout` matters for the long
operations: the CLI defaults to 300 s, while the interface submits without a deadline.

## Rules kept here

* Nothing is declared supported before it has been executed on this machine;
  `platform-tested.json` is filled only from real runs and `build_manifest.py` copies it into
  the manifest.
* An operation that cannot work says which engine or which model is missing, and names the page
  when a licence must be accepted in person. No operation pretends.
* `data/` is never replaced by an update, and weights are never deleted to tidy up.
* The Core is not modified: what is missing from the SDK is implemented here, in the Tool.
